## 2025-02-28 - Module-level Promise caching for fetch requests
**Learning:** When implementing a module-level Promise cache for `fetch` requests, it's critical to explicitly check `!res.ok` and throw an error, because `fetch` only rejects on network failures. Without this, a failed HTTP response (e.g., 404, 500) could be cached indefinitely, blocking successful retries. Additionally, separating the resolved data from the active fetch promise and returning the promise directly (removing `async` from the outer function) avoids unnecessary microtask overhead and prevents components from triggering loading states incorrectly on remounts.
**Action:** Always include error handling to clear or delete the cache entry if the promise rejects, explicitly check `!res.ok` to trigger the `.catch()` block for HTTP errors, and remove the `async` keyword from the outer function signature to return the Promise directly.
