## 2025-01-28 - Module-level Promise Caching for Redundant Network Requests
**Learning:** React components (especially dashboards fetching data from multiple APIs on mount) can trigger redundant network requests if they share a common service method and re-render/remount frequently. Returning a Promise and using async/await within a standard component lifecycle will re-fetch data on every mount. Wrapping the fetch call inside an `async` function creates microtask overhead, and failing to cache the active promise creates a race condition where multiple components might initiate identical requests simultaneously before the first one resolves.
**Action:** When a service method fetching external data is likely to be called repeatedly across component remounts without needing fresh data, implement a module-level cache (e.g., a `Map`) that stores the *Promise* itself, not just the resolved data. Remove the `async` keyword from the outer function signature so you can immediately return the cached Promise or store the newly created one. Always include error handling to remove rejected promises from the cache, preventing components from getting permanently stuck with failed request errors. Also, always provide a `forceRefresh` parameter to allow UI elements to bypass the cache when users explicitly request a data sync.
