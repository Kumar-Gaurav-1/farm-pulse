## 2023-10-25 - Promise Caching with TTL and Error Recovery
**Learning:** When implementing a module-level Promise cache for time-sensitive data (like exchange rates), you must include a Time-To-Live (TTL) to prevent serving permanently stale data. Crucially, because `fetch` only rejects on network errors, you must explicitly check `!res.ok` and throw an error to catch HTTP failures. If the promise rejects, you must immediately remove the active fetch promise from the cache map, otherwise all future successful retries are blocked indefinitely by the cached rejected state.
**Action:** Always include a TTL for time-sensitive cached data, explicitly handle HTTP errors in `fetch` promises, and ensure the `.catch()` block deletes the cache entry to allow future retries to succeed.
