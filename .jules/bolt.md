## 2024-10-27 - Module-level Promise Caching for React Component Remounts
**Learning:** In a Next.js application without a global state manager (e.g. Redux or Zustand), navigating between tabs triggers unmount and remount of functional components (like `MarketDashboard`). This causes expensive API calls, like `marketTrendSynthesis`, to re-fire unnecessarily on every navigation. Simple `useState` is insufficient as it gets wiped on unmount.
**Action:** Implement a module-level variable (outside the React component scope) to cache the `Promise` of the API call. By caching the `Promise` rather than just the resolved data, concurrent mounts are handled correctly and we only fetch once. Always include a mechanism (like `forceRefresh`) to clear this cache for manual user retries, and ensure the cache resets to `null` if the promise rejects to prevent permanently caching errors.
