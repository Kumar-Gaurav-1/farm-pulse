## 2024-05-18 - Optimized API Service Caching
**Learning:** Found that multiple components making requests for the same external API data (like `ApiServices.getExchangeRates()`) can cause redundant network calls, especially when components remount or when multiple widgets request the same baseline data simultaneously. A simple `Promise` cache combined with a Time-To-Live (TTL) data cache prevents both duplicate in-flight requests and excessive fetching of relatively static data.
**Action:** When working with API utility files, implement module-level caching (using `Map` for promises and timestamped data) for endpoints that return slowly-changing data (like daily exchange rates or benchmarks) to reduce latency from ~200ms down to <1ms for subsequent calls across the app lifecycle.
