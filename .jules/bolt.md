## 2025-02-21 - Module-Level Promise Cache for React Components
**Learning:** In Next.js architectures where components (like tabs in a dashboard) are frequently unmounted and remounted during navigation, `useEffect` hooks with empty dependency arrays (`[]`) will re-fire on every remount. This can cause redundant network and expensive AI calls if not managed. Caching just the resolved data can still lead to race conditions where multiple rapid remounts trigger redundant parallel requests before the first one finishes.
**Action:** When implementing an in-memory cache for client-side API requests across component remounts without a global state manager, cache the `Promise` itself rather than just the resolved data at the module level (outside the component scope). Always ensure there is a mechanism (e.g., a `forceRefresh` parameter) to bypass the cache for user-triggered manual refresh actions, and always clear the cache variable if the promise rejects to prevent failed requests from being cached indefinitely.
