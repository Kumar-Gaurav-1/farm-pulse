## 2024-10-10 - Caching Active Promises to Prevent Redundant Requests
**Learning:** When implementing module-level caches for API responses used in React components, it's critical to cache both the resolved data (with a TTL) AND the active in-flight `Promise`. If components unmount and remount quickly (e.g., switching tabs) while a fetch is still pending, the resolved cache won't have the data yet. Without caching the active promise, remounting triggers a brand new, redundant network request.
**Action:** Always maintain two separate `Map` objects when implementing fetch caches: one for the resolved data with expiration, and one for the active fetch promises. Remember to `delete` the active promise entry in a `finally` block to prevent blocking retries if the request fails.
