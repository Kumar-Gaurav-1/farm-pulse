## 2024-08-19 - [Performance Optimization: Module-Level Promise Cache for API Calls]
**Learning:** Caching expensive multi-REST/AI calls across React component remounts can be effectively achieved using a module-level Promise cache. This approach prevents redundant network requests when switching between views that unmount and remount components. By storing the Promise itself (rather than just the resolved data), concurrent requests from multiple components mounting simultaneously are handled correctly. Crucially, the cache must be reset to `null` if the Promise rejects, preventing failed network requests from being cached indefinitely and blocking future successful retries. It's also essential to implement a `forceRefresh` mechanism to bypass the cache during user-triggered manual refresh actions.
**Action:** When implementing a module-level Promise cache to prevent redundant API calls across React component mounts, always include error handling to clear or reset the cache to `null` if the promise rejects. Ensure there is a mechanism (e.g., a `forceRefresh` parameter) to bypass the cache when manual refresh actions occur.
